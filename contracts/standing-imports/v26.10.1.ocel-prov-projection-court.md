# OCEL 2.0 → W3C PROV projection court

CalVer: v26.10.1

Donors:
- OCEL 2.0 specification, 2023-10-16: https://www.ocel-standard.org/2.0/ocel20_specification.pdf
- W3C PROV-O Recommendation, 2013-04-30: https://www.w3.org/TR/2013/REC-prov-o-20130430/
- W3C PROV-CONSTRAINTS Recommendation, 2013-04-30: https://www.w3.org/TR/2013/REC-prov-constraints-20130430/

Decision: COMPOSE. OCEL owns object-centric event evidence; PROV owns provenance interchange and validity. This contract does not create a third event/provenance semantics.

## Projection boundary

Admitted projection:
- OCEL event -> prov:Activity.
- OCEL object version/value observed before/after an event -> prov:Entity only when the projection preserves the version/change boundary; an OCEL object identity by itself MUST NOT be collapsed into one timeless PROV Entity when doing so loses attribute history.
- OCEL E2O participation may project to prov:used / prov:wasGeneratedBy / qualified PROV relations only when the OCEL qualifier plus local projection rule establishes that direction. Mere adjacency MUST NOT choose use versus generation.
- OCEL O2O relationships remain OCEL evidence unless an independently admitted rule establishes a PROV relation. O2O adjacency is not derivation.
- OCEL timestamps may constrain PROV event ordering; they do not manufacture missing generation/use events.

## Negative knowledge

1. E2O adjacency != prov:used.
2. E2O adjacency != prov:wasGeneratedBy.
3. O2O adjacency != prov:wasDerivedFrom.
4. OCEL object identity != one timeless prov:Entity when attributes change through time.
5. PROV validity != OCEL conformance.
6. OCEL conformance != PROV validity.
7. A valid projection != truth, semantic equivalence, authorization, runtime authority, DO authority, or external standing.
8. Projection MUST preserve enough source identity to replay the OCEL evidence that produced each PROV assertion.

## Court

For each admitted fixture:
1. validate the source under the exact OCEL 2.0 contract;
2. project only relations justified by an explicit projection rule;
3. normalize and validate the result under PROV-CONSTRAINTS;
4. preserve source OCEL identifiers, projection-rule identifiers, and resulting PROV identifiers in the receipt;
5. replay the projection and require the same normalized PROV instance up to PROV equivalence;
6. independently apply local standing/authority admission.

Typed refusals:
- OCEL_PROV_DIRECTION_UNJUSTIFIED
- OCEL_PROV_HISTORY_COLLAPSE
- OCEL_PROV_RELATION_INVENTED
- OCEL_PROV_INVALID
- OCEL_PROV_REPLAY_DIVERGENCE
- OCEL_PROV_AUTHORITY_PROMOTION

Minimum falsifier: any locally accepted OCEL→PROV projection that invents a PROV causal direction from unqualified adjacency, loses an OCEL object-attribute change required to distinguish entity state, or is invalid under an applicable normative PROV constraint.

Authority ceiling: EVIDENCE_VALIDATION_ONLY.
Runtime authority: none.
Consequential authority: forbidden.

Retirement rule: bespoke event/provenance mappings are removable only after their admitted observable boundary is reproduced by this composition and its negative courts.
