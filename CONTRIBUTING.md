# Contributing

Contributions begin with an issue or draft pull request that states the exact base
SHA, intended semantic boundary, affected pack or consumer, acceptance command, and
falsifier. Prefer extending an existing marketplace pack over creating consumer
handwriting. Generated projections are not editing surfaces.

Every pull request must identify observed, admitted, executed, changed, verified,
inferred, refused, blocked, and unsupported facts separately. Do not claim ALIVE from
workflow existence, a named receipt, or an unexecuted plan.

Run `make verify`, `make receipt-verify`, and `make replay RECEIPT=...` where applicable.
