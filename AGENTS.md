# ggen-ecosystem operating doctrine

## Authority
This repository is the canonical composition root of the ggen ecosystem. Ontology/admission/profile sources outrank generated projections. The generated GitHub manufacturing workflow is a consequence of the live GGen rail and must not be hand-edited.

## Manufacture
- Prefer existing `ggen-marketplace` packs; do not create a new pack here unless reusable knowledge cannot live in an existing one.
- Project observations and admission data belong here; reusable executable knowledge belongs in `ggen-marketplace`.
- Generated outputs are never editing surfaces.
- The real GGen source and pack marketplace are checked out as git submodules of this repo (`vendor/ggen`, `vendor/ggen-marketplace` — see `.gitmodules`), not merely referenced by pinned commit SHA. `Dockerfile` builds a composed image (real `ggen` binary from `vendor/ggen` + the real `vendor/ggen-marketplace/packs/` tree) published by `.github/workflows/ggen-ecosystem-container.yml`; `.github/workflows/ggen-ecosystem-sync.yml` runs `ggen sync run` inside that pinned container (`container: ghcr.io/seanchatmangpt/ggen-ecosystem:<tag>`, default `v26.8.28`) rather than downloading a binary. `ggen-marketplace` also exposes a reusable composite action (`packs/github-actions-pack/examples/consume-github-actions-pack/.github/actions/use-ggen-ecosystem/action.yml`) that runs `docker run ... ggen sync run` against the same image for consumer repos. See `ecosystem.lock.toml` for the exact pinned producer identities.

## Certification
`certification/mfact.toml` and `certification/artifacts.toml` define the mfact-derived certification court. Its authority ceiling is `VERIFY`: it may bind producer identities, artifact ownership, receipts, replay evidence, Git lineage, and scoped standing, but it may not manufacture an `ALIVE` claim or perform `DO`.

Authority comes from the artifact ledger rather than filename conventions. GGen-manufactured workflows are projections with zero standing authority. Historical receipts remain admissible historical evidence but may not certify a newer exact head as `ALIVE`; load-bearing drift after the receipted subject lowers the certification ceiling until fresh evidence exists. Contradictory producer, ledger, receipt, or lineage identities must fail closed with typed `REFUSED` standing. Use `just certify-test` for promotion/refusal falsifiers and `just certify` for the observational certification court. `.github/workflows/mfact-certification.yml` is an independent read-only verifier, not a manufactured workflow projection.

## DfCM
Preserve -> Fence -> Calculus -> Exclusions -> Falsifier -> Extension -> Operationalization.
Maximize lawful reversible option capital before irreversible selection. A failed edge is topology, not graph failure. Bound possibilities by ontology, capability, authority, cost, evidence, and explicit exclusions.

## Execution
`SELECT`, `CONSTRUCT`, and `DO` are distinct. Only a receipted broker may perform `DO`. Hooks emit intents only. CI is evidence transport, not authority.

## Standing vocabulary
Use only `UNKNOWN`, `PARTIAL_ALIVE`, `ALIVE`, `BLOCKED`, `BUILD_BROKEN`, `UNSUPPORTED`, and typed `REFUSED`. Inspection is not execution; workflow definition is not workflow success; connector object is not a mounted tree; a named receipt is not a verified receipt.

## GitHub catalog
The maximal public scope is the complete owner predicate `owner=seanchatmangpt AND visibility=public`. Catalog membership is observation only. Private repository identities must not be published from this public root merely because tooling can read them.

## Repository workflow
Resolve `main` to an exact SHA, use a purpose branch, never silently move the base, verify the exact head, and merge only the inspected head when authorized. Preserve typed failures rather than smoothing them over.

## Generated directories
`.github/workflows/ggen-ecosystem-sync.yml` is generated by GGen. `generated/`, `consumer/`, and `.ggen-v2/` may also be manufactured projections. Repair their semantic source or pack when output is wrong.
